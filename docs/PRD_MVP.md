# SkyCast 4 周 MVP PRD

## 1. 目标

在 4 周内交付一个可安装、可演示、可评估的 Android 原型，证明“多源气象数据能够转化为摄影决策”，而不是证明已经具备全国商业化能力。

## 2. 成功标准

- 用户可在 3 分钟内完成“查看机会—理解原因—选择地点—查看风险”；
- 至少完成 1 个晚霞和 1 个强对流历史案例回放；
- 每个 AI 结果包含来源、时间、置信度和模型版本；
- 短临模型必须与 persistence baseline 对比；
- Android 主路径在无网络时仍能显示最近一次成功同步的数据；
- 仓库可按 README 在新环境中复现核心测试。

## 3. 首发页面

### 3.1 城市首页

用户故事：作为摄影爱好者，我希望打开应用后立刻知道今天有什么值得拍的景观。

验收标准：

- 显示城市、当前天气、日出日落和数据更新时间；
- 显示晚霞/朝霞机会卡；
- 数据过期时显示明显状态，不继续展示为实时结果；
- 点击机会卡进入评估详情。

### 3.2 场景评估详情

用户故事：作为准备出发的用户，我希望知道评分依据和最佳时间，而不是只看到一个分数。

验收标准：

- 展示 0～100 分、概率、置信度；
- 展示预计染色起点、峰值和终点；
- 展示至少 2 个有利因素和 1 个不利/不确定因素；
- 展示模型版本、数据来源和观测时间；
- 提供“拍到了/没拍到/未出发”反馈入口。

### 3.3 雷达与事件时间轴

用户故事：作为强天气摄影用户，我希望回看回波演变并理解系统的预测依据。

验收标准：

- 至少播放最近 12 帧或一组历史样例；
- 时间轴可暂停、拖动和改变播放速度；
- 地图显示官方预警边界或测试多边形；
- 显示数据时间，不把文件下载时间当成观测时间。

### 3.4 短临研判

用户故事：作为用户，我希望看到风暴未来可能出现的范围以及不确定性。

验收标准：

- 输出 15/30/45/60 分钟结果；
- 显示概率范围或误差锥，不输出虚假的精确轨迹；
- 同时显示 persistence baseline 和当前模型评估结果；
- 输入过期或缺帧时停止生成结果并说明原因。

## 5. 数据降级策略

| 问题 | 用户表现 | 系统动作 |
|---|---|---|
| 雷达超过 12 分钟 | 显示“雷达数据过期” | 停止短临和路线建议 |
| 卫星超过 30 分钟 | 降低置信度 | 使用预报云量并标注降级 |
| 预报服务失败 | 显示本地缓存 | 不声称为最新结果 |
| 模型失败 | 显示规则基线 | 记录错误和输入版本 |
| 官方预警升级 | 高优先级风险卡 | 取消冲突地点推荐 |

阈值属于产品策略配置，后续必须通过真实数据延迟分布校准。

## 6. 非功能需求

- 时间统一以 UTC 存储，以用户时区显示；
- 空间数据内部统一 WGS84，并显式记录 CRS；
- API 和日志不得包含地图、天气服务密钥；
- 大栅格不直接通过 JSON 返回，使用瓦片或对象存储；
- 客户端本地保留最近一次成功同步结果；
- 关键决策具备 requestId、modelVersion 和 provenance；
- Android 首版以 ARM64 为主，C++ 保留桌面测试目标。

## 7. 本期不做

- 对社会发布自生成气象预警；
- 持续后台追踪用户位置；
- 自动引导用户接近风暴；
- 未经授权抓取商业天气或地图数据；
- 没有评估基线的端到端大模型预测。

## 8. Definition of Done

一个功能只有同时满足以下条件才算完成：

- 用户故事和验收标准已更新；
- 代码通过自动测试和静态检查；
- 异常、缺测和过期路径已实现；
- 数据来源和模型版本可见；
- README 或相应文档已更新；
- Pull Request 已完成自检并合并；
- 有可录制的用户操作路径。
